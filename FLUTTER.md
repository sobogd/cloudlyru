# CloudlyRu — мобильное приложение (Flutter)

> Единственный клиент CloudlyRu: приложение на Flutter — Android и macOS из одной кодовой базы.
> История проекта — перенос веб-клиента (`web/src`) и старого нативного синхронизатора (`android/`)
> в одно приложение; оба каталога из репозитория удалены (коммит 407a490), поэтому упоминания их
> файлов ниже — исторические ориентиры, сверять по ним нечего. Источник истины — код `flutter/lib/`
> и `src/`. Настольная сборка macOS живёт в `flutter/macos/` (`flutter build macos`, нужен Xcode);
> iOS-сборки в проекте нет.
>
> Статус: приложение реализовано и релизится (`version: 1.0.0+50`), экраны из раздела
> «Экран → компоненты» есть в коде. Где текст расходится с кодом — это сказано прямо.

## Решения (зафиксированы)

| Вопрос | Решение |

| Модели | Руками, в `lib/api/models.dart` (больше тридцати классов): свой разбор JSON, `toJson` у моделей нет — тела запросов собирают экраны. `freezed`/`json_serializable` объявлены в `pubspec.yaml`, но генераторов в проекте нет: ни одного `.g.dart`/`.freezed.dart`, ни `copyWith` |
| Видео-превью | Новые превью — **H.264 (1080)**, играются везде; каскад фолбэка прежний: превью → оригинал (`video-preview?src=original`) — он же прикрывает старые AV1-превью |
| Тело писем | **WebView** (`webview_flutter`): письма — это разметка для браузерного движка (таблицы, медиазапросы, inline-стили), разбор её на виджеты врёт. Скрипты на странице включены только для замера высоты, чужие режет CSP |
| Сетка медиа | `GridView.builder` с `SliverGridDelegateWithFixedCrossAxisCount`: клетки фиксированного размера, окно загрузки считается от позиции скролла. Скрабера (перетаскиваемого ползунка по месяцам) нет — месяц видимой части показывается подписью в шапке |
| Кластеризация карты | Своя: миниатюра + счётчик, клетка по мировым пикселям (`flutter_map` + OSM) |
| Скачивание/открытие | Во временную папку приложения + `open_filex` (докачка, sha256, атомарный перенос) |

## Рамки

- **6 вкладок**: Файлы, Почта, Медиа, Карта, Корзина, Настройки (нижний остров).
- **Альбомы и Шаринг** в приложение не перенесены: шаринг убран из продукта целиком (и из API),
  альбомы остались только ручками API без интерфейса.
- **Веб-клиента нет**: браузерных страниц сервер не отдаёт, приложение — единственный клиент.
- `applicationId` — `ru.cloudly.sync` и подпись из `flutter/android/keystore.properties`:
  приложение встаёт поверх уже установленного на телефоне. Релиз собирает
  `.github/workflows/android.yml` из `flutter/`.

## Авторизация — сессия для интерфейса, device-токен для синхронизации

Так в коде (`lib/api/cloudly_api.dart`), а не так, как задумывалось на старте:

1. `POST /auth/login` (login+password) → cookie веб-сессии, она же `cl_session`. Пароль не храним.
2. Весь интерфейс (файлы, почта, медиа, карта, корзина, настройки) ходит этой cookie: ручки
   почты и выпуска токенов помечены `@SessionOnly` и device-токену отвечают 403.
3. Для синхронизации под сессией выпускается device-токен (`POST /auth/tokens`, `label` —
   «flutter»), он лежит в `flutter_secure_storage`: корень зеркала сервер заводит устройству,
   то есть токену. Им ходит только синхронизатор (`lib/sync/net/sync_api.dart`, `Bearer`).
4. «Выйти» = `DELETE /auth/me/token` (гасит токен) + `POST /auth/logout` (гасит сессию).
5. `/auth/me` даёт `photoFolderId`, `mirrorFolderId`.

Cookie-сессия на сервере остаётся обязательной: это единственный способ войти с телефона.

Экраны: `Login` (логин/пароль/ошибка) → `Shell` (нижний остров, активная вкладка подсвечена).

## Экран → компоненты

### Файлы (ядро)
- Стек навигации по папкам; список: папки + файлы с миниатюрами 44×44 (`/files/:id/thumb`), пустое состояние.
- Шапка: «вверх», «инфо о папке», «новая папка», «загрузить» (multi-pick), «вставить» (серверный clipboard `set/paste/clear`).
- `FileDetail`: метадата (имя/тип/размер/путь/SHA-256), превью (фото/видео/PDF постранично), копировать/вырезать/переименовать/удалить/скачать, разархивация zip с прогрессом, ссылка на письмо-вложение.
- `FolderDetail`: метадата, переименовать, вырезать, удалить.

**Загрузка** (исторически — порт удалённого `web/src/api.ts`):
1. sha256 стримингом (`crypto`), прогресс «считаю sha256».
2. `POST /uploads` (direct) → дедуп либо загрузка.
3. Прямая загрузка в S3 по presigned-URL: части идут последовательно (размер части называет сервер, по умолчанию 16 МБ), у каждой части свой ETag, прогресс по байтам и до 3 попыток с растущей паузой; ссылка берётся заново на каждую попытку. Если прямая загрузка недоступна (`DirectUnavailable`) — фолбэк `relay` чанками через сервер.
4. `POST /uploads/:id/complete` → фаза «verify».
5. Панель: «x из N», отмена, повтор упавших.

### Корзина
Список (папки+файлы, дата удаления), восстановить, очистить целиком.

### Настройки
- Аккаунт (`login`, выйти).
- Приложения (WebDAV/Finder): список app-токенов **только на чтение** — метка, последнее
  использование. Ни выпуска, ни отзыва, ни строки подключения WebDAV в приложении нет: ручки
  `POST /auth/tokens` и `DELETE /auth/tokens/:id` требуют веб-сессию, а интерфейса к ним сейчас
  нет нигде (веб-клиент удалён) — вызвать их можно только запросом к API. Себе device-токен
  выпускает сам синхронизатор.
- Очередь превью: остаток по типам, пауза, пересчитать, очистить, диск сервера; отдельная страница ошибок с ретраем и пагинацией.
- Почтовые аккаунты: статусы, «проверить», полл при синхронизации.

### Медиа
- Виртуализированная сетка 50×50: `count` + `range?offset&limit` по видимой части (дебаунс 400 мс), полный скролл сразу.
- Статусы неготовых превью дозапрашиваются у сервера (`POST /media/status`) для видимых клеток раз в 5 с — пока превью не собралось или не кончился запас попыток; кадры с `previewState = 'impossible'` не опрашиваются.
- Месяц видимой части — подписью в шапке (`mediaMonths`). Скрабера и прыжка к месяцу нет.
- `MediaViewer` (модалка): свайп, щипковый/двойной зум, листание по индексу, футер метадаты (`mediaInfo`), удаление, переход на OSM по геометке. Переиспользуется Картой.

### Карта
- `flutter_map` + OSM, подпись авторов обязательна (политика OSM).
- Кластеризация своя: миниатюра + счётчик, тап открывает группу в `MediaViewer`.
- «Показать все» и первый вид по самой «фотографируемой» клетке. Центр и зум не сохраняются: вид выставляется заново при каждом монтировании экрана, то есть после перезахода карта возвращается к своей «домашней» клетке.

### Почта
- Три папки (входящие/исходящие/корзина), виртуализированный список с фиксированной высотой строки (76), теги аккаунтов, аватары-фавиконы.
- Просмотр: шапка, тело письма в WebView (`mail_body_web.dart`) с переключателем «показать как текст», вложения (скачать/открыть деталку), ответить/всем/переслать, скачать `.eml`; в корзине — восстановить или удалить навсегда, во входящих — удалить.
- Композер: новое/ответ/пересылка (`reply-context` считает сервер), вложения из контекста. Авто-черновика нет: незакрытая форма при уходе с экрана теряется.
- Кнопка «Проверить» в списке перечитывает только ленту открытой папки. Настоящий проход по IMAP запускает кнопка «Проверить» в «Настройках» (`POST /mail/sync`), и ответ приходит сразу — конца прохода никто не ждёт.

## Синхронизация телефона (исторически — перенос из удалённого нативного клиента)

Синхронизатор — часть этого приложения (в нативном клиенте он был отдельным, того клиента и
его файлов в репозитории больше нет): выбор папок разделов, очередь ручной выгрузки и
двустороннее зеркало. Интерфейс приложения ходит веб-сессией (cookie), а синхронизация —
**device-токеном** в `Authorization: Bearer`: корень зеркала сервер заводит именно устройству,
веб-сессии он его не отдаёт вовсе.

Токен выпускается один раз (`POST /auth/tokens` под сессией) и переиспользуется: новый токен —
это новый корень зеркала, и после каждого входа-выхода в облаке появлялась бы ещё одна папка
с тем же содержимым. Хранится он в `flutter_secure_storage`, отзывается при выходе из аккаунта.

Третий столбец — исторический: из какого файла удалённого `android/` перенесён слой. Сверять
его не с чем, живой код — во втором столбце.

| Слой | Файлы | Откуда порт (удалённый `android/`) |
|---|---|---|
| Разделы, правила отбора | `lib/sync/section.dart`, `lib/sync/device/media_rules.dart` | `data/Section.kt`, `device/MediaRules.kt` |
| Выбор папок | `lib/sync/data/selection.dart`, `data/selection_rules.dart`, `lib/sync/ui/folder_tree_screen.dart` | `data/Selection.kt`, `ui/FolderTreeScreen.kt` |
| Чтение телефона | `lib/sync/device/device_files.dart`, `device/hasher.dart` | `device/DeviceFiles.kt`, `device/Hasher.kt`, `ui/FileListScreen.kt` |
| Номер файла и наблюдение | `lib/sync/device/native_stat.dart` (номер через `stat(2)` по FFI), `device/native_fs.dart` (корни, доступ, наблюдение) | `flutter/android/.../SyncBridge.kt` (удалён), `ui/UiCommon.kt`, `mirror/MirrorWatcher.kt` |
| Состояние | `lib/sync/data/queue_store.dart`, `data/mirror_store.dart`, `data/sync_prefs.dart` | `data/QueueStore.kt`, `mirror/MirrorStore.kt`, `data/Prefs.kt` |
| Сеть | `lib/sync/net/sync_api.dart`, `net/device_token.dart` | `net/Api.kt`, `net/Dto.kt` |
| Очередь | `lib/sync/queue/*`, `lib/sync/ui/queue_screen.dart` | `queue/*.kt`, `ui/QueueScreen.kt` |
| Зеркало | `lib/sync/mirror/*` | `mirror/*.kt` |
| Интерфейс синхронизации | `lib/features/settings/sync_panel.dart` (группа «Синхронизация»: разрешение, папки разделов, очередь, состояние зеркала) | `ui/QueueScreen.kt`, `ui/MirrorCard.kt` |
| Сборка всего | `lib/sync/sync_controller.dart` (провайдер `syncControllerProvider`) | `App.kt` |

Что оставалось нативным и почему: раньше — доступ ко всем файлам, тома памяти, номер файла и
события файловой системы (мост `SyncBridge.kt`). **Теперь нативного кода в проекте нет вовсе:**

- ключ файла (том и номер в нём) берётся `stat(2)` через `dart:ffi`
  (`lib/sync/device/native_stat.dart`) — с раскладкой структуры на каждую платформу и самопроверкой
  (размер файла из `stat` сверяется с `File.lengthSync`). Том идёт в ключе не для красоты: номер
  уникален только внутри тома, и без него копия файла на другой карте памяти выглядела бы
  переименованием и увезла бы облачную запись на чужой путь. У съёмного тома номер устройства
  меняется при подключении, поэтому «том не тот» читается как «сравнить нельзя», а не «изменился»;
- корни, признак доступа и наблюдение за папками — обычный Dart: `Directory.list`, `Directory.watch`,
  `Process.run('getprop')`; на macOS рекурсивный `Directory.watch` идёт через FSEvents, на Android —
  опрос дат папок (рекурсивного наблюдения там нет);
- наблюдение осталось ускорителем: без него синхронизация работает, только переименование
  обходится повторной выгрузкой, а новое замечается проходом, а не событием.

Kotlin-файлы и объявления службы задания из манифеста удалены, активность объявлена прямо
движком (`io.flutter.embedding.android.FlutterActivity`) — своей `MainActivity` в проекте больше нет.

Файлы в системном выборе (`CloudlyDocumentsProvider`) и ответ на `GET_CONTENT` чужого
приложения (`CloudlyPickerActivity`) не перенесены: это `ContentProvider` и `Activity`,
из Dart их не написать. Вместе с удалением старого нативного приложения они пропали совсем —
в облако из чужого приложения файл сейчас не отправить. На телефоне их нет с тех пор, как
поверх нативного клиента встал Flutter-APK (тот же `applicationId`), так что фактически
это не потеря, а фиксация: если понадобится вернуть — писать провайдер заново на Kotlin
в `flutter/android/`.

### Когда идёт синхронизация

**Только пока приложение запущено.** Фонового прохода нет: задания `JobScheduler`
(`SyncJobService.kt`, `SyncJobScheduler.kt`, `SyncBootReceiver.kt`) и весь слой
`lib/sync/background/*` удалены вместе с нативным кодом. Что работает вместо них:

- мгновенный режим (`lib/sync/mirror/mirror_live.dart`): опрос головы журнала раз в 1,5 с
  (в свёрнутом приложении — раз в 30 с) и проход по событию файловой системы;
- наблюдение за папками (`NativeFs.watch`): на macOS рекурсивный `Directory.watch` на FSEvents —
  одно наблюдение на всё дерево, на Android обход дерева один раз и опрос дат папок раз в 15 с
  плюс просьба пройти сверку раз в 5 минут (правка содержимого дату папки не меняет);
- сторож (`SyncController._startWatchdog`): раз в минуту выгружает ждущее, раз в пять минут
  наполняет очередь заново;
- при запуске `SyncController.checkAndResume` ставит наблюдение, наполняет очередь и запускает
  проход, если он встал, — этим и догоняется всё, что накопилось за время закрытого приложения.

Чего это стоит: пока приложение закрыто (или выгружено системой), синхронизации нет вовсе —
ни ночного прохода, ни подъёма после перезагрузки, ни пробуждения в Doze. Расхождения копятся
и догоняются одним заходом при следующем запуске. Кнопка «Проверить и догнать» в «Настройках»
заставляет проход пойти прямо сейчас, если он закончился минуту назад.

`workmanager` — очевидный способ вернуть фон — осознанно не взят: это чужая зависимость с
нативным кодом внутри и минимумом пятнадцать минут между проходами, а выигрыш только в том,
что приложение закрыто. Решение владельца: автоматика нужна, пока приложение открыто.

Выключателя автоматики нет и не было: прежний флаг `paused` в базе зеркала
(`MirrorStore.keyPaused`) только снимается при старте и никогда не читается. Предохранители
движка не ослаблены: подтверждение массового удаления из фона не выставляется — фона нет,
а из приложения удаления подтверждает человек.

Кнопка «Открыть настройки» рядом с подсказкой о доступе на Android открывает карточку
приложения (`package:` через `url_launcher`), а не сразу нужный экран: прямого
`MANAGE_APP_ALL_FILES_ACCESS_PERMISSION` из Dart не отправить. На части прошивок кнопка
не откроет ничего — путь руками написан в той же подсказке.

### Что нужно при первом запуске

1. Выдать «доступ ко всем файлам» — без него не видно ни дерева, ни содержимого (кнопка в
   «Настройках» → «Синхронизация»).
2. Отметить папки разделов «Файлы» и «Фото»: выбор прежнего нативного приложения не читается —
   он лежал в его собственных настройках, а Flutter пишет свой список (и это единственный клиент).
3. Убедиться, что не мешает старый токен устройства: корень зеркала заводится на каждый токен
   (`<Имя устройства> - Файлы`), поэтому у прежнего клиента в облаке может остаться своя папка.
   Отозвать ненужный токен можно ручкой `DELETE /auth/tokens/:id` (в приложении список токенов
   только на чтение), после чего папку можно удалить как обычную.


## Настольная сборка (macOS)

Та же кодовая база собирается под macOS: каталог `flutter/macos/`, сборка `flutter build macos`
(нужен Xcode, CocoaPods не нужен — проект на SwiftPM). Своего нативного кода на маке нет,
как и на Android: всё, что нужно синхронизации, лежит в Dart, а различия платформ — четыре
ветки в `lib/sync/device/native_fs.dart` и раскладки `struct stat` в `native_stat.dart`.

Что настроено руками поверх шаблона Flutter:

- `PRODUCT_NAME = Cloudly`, `PRODUCT_BUNDLE_IDENTIFIER = ru.cloudly.sync` — тот же идентификатор,
  что `applicationId` на Android: система отсчитывает от него выданные права (TCC, Full Disk Access);
- песочница выключена в обоих `.entitlements`: в песочнице произвольные папки пользователя
  доступны только через security-scoped bookmarks, то есть через нативный код. Вне App Store
  песочница не обязательна;
- закрытие окна завершает приложение — так устроен шаблон Flutter
  (`applicationShouldTerminateAfterLastWindowClosed`). Синхронизация идёт, пока приложение
  запущено, поэтому закрывать окно насовсем нельзя: свернуть — можно.

Обновление на маке — кнопкой в «Настройках», как на телефоне, но установщика там нет:
приложение скачивает архив со сборкой (`/app/macos`), проверяет размер и sha256, кладёт рядом
скрипт-помощник и выходит, а помощник распаковывает архив (`ditto`), ставит новую сборку на место
прежней и запускает её (`lib/features/settings/macos_update.dart`). Прежняя сборка сдвигается
в `<бандл>.old` и возвращается на место, если новую поставить не удалось; ход замены пишется
в `replace.log` рядом с архивом. Права на запись рядом со сборкой проверяются заранее — иначе
человек остался бы без приложения после выхода.

## Релиз

Только через git и GitHub Actions; `adb install` — лишь когда это прямо попросили (например,
для проверки сборки на конкретном телефоне).

1. Поднять `versionCode` в `flutter/pubspec.yaml` (`version: <versionName>+<versionCode>`, сейчас
   `1.0.0+50`): телефон узнаёт об обновлении только по нему, и скрипт публикации не даёт
   положить сборку с тем же или меньшим номером.
2. Закоммитить и запушить в `main`: `./scripts/gh-push.sh main` (токен берётся из `~/work/.env`
   локально, в логи не попадает).
3. Запустить сборку: `gh workflow run android.yml --repo sobogd/cloudlyru`, дождаться успеха
   (`gh run watch <id> --exit-status`).
4. Что делает workflow (`.github/workflows/android.yml`): собирает подписанный
   release-APK ключом из секретов (`flutter/android/keystore.properties`) и публикует его в S3.
   Тестов в проекте нет — проверка перед выпуском это `flutter analyze` и запуск приложения
   на телефоне.
   Постоянная ссылка —
   `https://files.iq-factura.com/apk`, её отдаёт и ручка `/api/v1/app/android`, по которой
   приложение в «Настройках» показывает доступное обновление.
5. Настольная сборка — тем же порядком, но своим workflow:
   `gh workflow run macos.yml --repo sobogd/cloudlyru` (`.github/workflows/macos.yml`) собирает
   `Cloudly.app` на мак-раннере, кладёт рядом архив и публикует его через
   `scripts/publish-macos.mjs`. Номер сборки общий с Android — то же `+N` из `pubspec.yaml`;
   поднимать его достаточно один раз для обеих платформ. Постоянная ссылка —
   `https://files.iq-factura.com/macos`, версия для кнопки — `/api/v1/app/macos`.
   Подписи Developer ID у настольной сборки нет: для обновления кнопкой из приложения она
   не нужна (карантин ставит браузер, а не наш HTTP-клиент), а для передачи на другой мак
   её придётся добавить вместе с нотаризацией.
