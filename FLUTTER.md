# CloudlyRu — мобильное приложение (Flutter)

> Единственный клиент CloudlyRu: Android-приложение на Flutter. История проекта — перенос
> веб-клиента (`web/src`) и старого нативного синхронизатора (`android/`) в одно приложение;
> и веб-клиент, и нативное приложение из репозитория удалены, ссылки на их файлы ниже —
> исторические. Ту же кодовую базу позже можно собрать под macOS и iPad (ради этого и выбран
> Flutter).
>
> Статус: план согласован, реализация — с милестоуна 1.

## Решения (зафиксированы)

| Вопрос | Решение |
|---|---|
| UI-библиотека | **Material 3** (встроенная) + тёмная тема под текущий вид веба. Фирменные части (остров-навигация, скрабер, кластеризация карты) — свои виджеты на примитивах Material |
| Состояние | **Riverpod** (общая очередь загрузки — провайдер над вкладками) |
| Сеть | **Dio** + `api.dart` — построчный порт `api.ts` (те же пути, типы, ошибки с `code`) |
| Модели | **freezed + json_serializable** (порт всех TS-интерфейсов) |
| Видео-превью | Новые превью — **H.264 (1080)**, играются везде; каскад фолбэка прежний: превью → оригинал (`video-preview?src=original`) — он же прикрывает старые AV1-превью |
| Тело писем | **WebView** (`webview_flutter`): письма — это разметка для браузерного движка (таблицы, медиазапросы, inline-стили), разбор её на виджеты врёт. Скрипты на странице включены только для замера высоты, чужие режет CSP |
| Сетка медиа + скрабер | Кастомный рендер (`Sliver`/`CustomScrollView`), математику из `media.tsx` переносим дословно |
| Кластеризация карты | Своя: миниатюра + счётчик, клетка по мировым пикселям (`flutter_map` + OSM) |
| Скачивание/открытие | Во временную папку приложения + `open_filex`; порт `downloadToFile` (докачка, sha256, атомарный перенос) |

## Рамки

- **6 вкладок**: Файлы, Почта, Медиа, Карта, Корзина, Настройки (нижний остров).
- **Альбомы и Шаринг** не переносим: шаринг убран из продукта целиком (и из API), альбомы
  остались только ручками API без интерфейса.
- **Веб-клиента нет**: браузерных страниц сервер не отдаёт, приложение — единственный клиент.
- `applicationId` — `ru.cloudly.sync` и подпись из `flutter/android/keystore.properties`:
  приложение встаёт поверх уже установленного на телефоне. Релиз собирает
  `.github/workflows/android.yml` из `flutter/`.

## Авторизация — сессия для интерфейса, device-токен для синхронизации

Так в коде (`lib/api/cloudly_api.dart`), а не так, как задумывалось на старте:

1. `POST /auth/login` (login+password) → cookie веб-сессии, она же `cl_session`. Пароль не храним.
2. Весь интерфейс (файлы, почта, медиа, карта, корзина, настройки) ходит этой cookie: ручки
   почты и выпуска токенов помечены `@SessionOnly` и device-токену отвечают 403.
3. Для синхронизации под сессией выпускается device-токен (`POST /auth/tokens`, `label` —
   «flutter»), он лежит в `flutter_secure_storage`: корень зеркала сервер заводит устройству,
   то есть токену. Им ходит только синхронизатор (`lib/sync/net/sync_api.dart`, `Bearer`).
4. «Выйти» = `DELETE /auth/me/token` (гасит токен) + `POST /auth/logout` (гасит сессию).
5. `/auth/me` даёт `photoFolderId`, `mirrorFolderId`.

Cookie-сессия на сервере остаётся обязательной: это единственный способ войти с телефона.

Экраны: `Login` (логин/пароль/ошибка) → `Shell` (нижний остров, активная вкладка подсвечена).

## Экран → компоненты

### Файлы (ядро)
- Стек навигации по папкам; список: папки + файлы с миниатюрами 50×50 (`/files/:id/thumb`), пустое состояние.
- Шапка: «вверх», «инфо о папке», «новая папка», «загрузить» (multi-pick), «вставить» (серверный clipboard `set/paste/clear`).
- `FileDetail`: метадата (имя/тип/размер/путь/SHA-256), превью (фото/видео/PDF постранично), копировать/вырезать/переименовать/удалить/скачать, разархивация zip с прогрессом, ссылка на письмо-вложение.
- `FolderDetail`: метадата, переименовать, вырезать, удалить.

**Загрузка** — точный порт `uploadFile` из `api.ts`:
1. sha256 стримингом (`crypto`), прогресс «считаю sha256».
2. `POST /uploads` (direct) → дедуп либо загрузка.
3. Прямая загрузка в S3 по presigned-URL (прогресс по байтам, ETag, watchdog «нет байтов 45 с», ретраи) → при `DirectUnavailable` фолбэк `relay` чанками через сервер.
4. `POST /uploads/:id/complete` → фаза «verify».
5. Панель: «x из N», отмена, повтор упавших.

### Корзина
Список (папки+файлы, дата удаления), восстановить, очистить целиком (порт `TrashPage`).

### Настройки
- Аккаунт (`login`, выйти).
- Токены приложений (list/create/revoke, показ свежего токена один раз + строка WebDAV).
- Очередь превью: остаток по типам, пауза, пересчитать, очистить, диск сервера; отдельная страница ошибок с ретраем и пагинацией.
- Почтовые аккаунты: статусы, «проверить», полл при синхронизации.

### Медиа
- Виртуализированная сетка 50×50: `count` + `range?offset&limit` по видимой части (дебаунс), полный скролл сразу; статусы неготовых превью — `mediaStatus`.
- Скрабер с подписью месяца (`mediaMonths`), липкий месяц в шапке.
- `MediaViewer` (модалка): свайп, щипковый/двойной зум, листание по индексу, футер метадаты (`mediaInfo`), удаление, переход на OSM по геометке. Переиспользуется Картой.

### Карта
- `flutter_map` + OSM, подпись авторов обязательна (политика OSM).
- Кластеризация своя: миниатюра + счётчик, тап открывает группу в `MediaViewer`.
- «Показать все», первый вид по самой «фотографируемой» клетке, сохранение центра/зума.

### Почта
- Три папки (входящие/исходящие/корзина), виртуализированный список с фиксированной высотой строки (порт `mail.tsx`), теги аккаунтов, аватары-фавиконы.
- Просмотр: шапка, тело письма в WebView (`mail_body_web.dart`) с переключателем «показать как текст», вложения (скачать/открыть деталку), ответить/всем/переслать, удалить/восстановить/стереть, скачать `.eml`.
- Композер: новое/ответ/пересылка (`reply-context` считает сервер), вложения, авто-черновик.
- «Проверить почту» с ожиданием конца серверного прохода.

## Синхронизация телефона (перенос из нативного клиента)

Нативный синхронизатор стал частью этого приложения: выбор папок разделов,
очередь ручной выгрузки и двустороннее зеркало. Интерфейс приложения ходит веб-сессией
(cookie), а синхронизация — **device-токеном** в `Authorization: Bearer`: корень зеркала
сервер заводит именно устройству, веб-сессии он его не отдаёт вовсе.

Токен выпускается один раз (`POST /auth/tokens` под сессией) и переиспользуется: новый токен —
это новый корень зеркала, и после каждого входа-выхода в облаке появлялась бы ещё одна папка
с тем же содержимым. Хранится он в `flutter_secure_storage`, отзывается при выходе из аккаунта.

| Слой | Файлы | Откуда порт |
|---|---|---|
| Разделы, правила отбора | `lib/sync/section.dart`, `lib/sync/device/media_rules.dart` | `data/Section.kt`, `device/MediaRules.kt` |
| Выбор папок | `lib/sync/data/selection.dart`, `data/selection_rules.dart`, `lib/sync/ui/folder_tree_screen.dart` | `data/Selection.kt`, `ui/FolderTreeScreen.kt` |
| Чтение телефона | `lib/sync/device/device_files.dart`, `device/hasher.dart`, `lib/sync/ui/section_screen.dart` | `device/DeviceFiles.kt`, `device/Hasher.kt`, `ui/FileListScreen.kt` |
| Мост к Android API | `flutter/android/.../SyncBridge.kt`, `lib/sync/device/native_fs.dart` | `ui/UiCommon.kt`, `mirror/MirrorWatcher.kt` |
| Состояние | `lib/sync/data/queue_store.dart`, `data/mirror_store.dart`, `data/sync_prefs.dart` | `data/QueueStore.kt`, `mirror/MirrorStore.kt`, `data/Prefs.kt` |
| Сеть | `lib/sync/net/sync_api.dart`, `net/device_token.dart` | `net/Api.kt`, `net/Dto.kt` |
| Очередь | `lib/sync/queue/*`, `lib/sync/ui/queue_screen.dart` | `queue/*.kt`, `ui/QueueScreen.kt` |
| Зеркало | `lib/sync/mirror/*`, `lib/sync/ui/mirror_card.dart` | `mirror/*.kt`, `ui/MirrorCard.kt` |
| Сборка всего | `lib/sync/sync_controller.dart` (провайдер `syncControllerProvider`) | `App.kt` |
| Фон | `lib/sync/background/*`, `flutter/android/.../SyncJobService.kt`, `SyncJobScheduler.kt`, `SyncBootReceiver.kt` | `mirror/MirrorScheduler.kt`, `MirrorJobService.kt`, `MirrorBootReceiver.kt` |

Что остаётся нативным и почему: доступ ко всем файлам, тома памяти, номер файла в файловой
системе и события файловой системы — в Dart для них API нет (`SyncBridge.kt`). Обход дерева,
чтение и запись, хэш, сеть и вся логика сверки — на Dart.

Файлы в системном выборе (`CloudlyDocumentsProvider`) и ответ на `GET_CONTENT` чужого
приложения (`CloudlyPickerActivity`) не перенесены: это `ContentProvider` и `Activity`,
из Dart их не написать. Вместе с удалением старого нативного приложения они пропали совсем —
в облако из чужого приложения файл сейчас не отправить. На телефоне их нет с тех пор, как
поверх нативного клиента встал Flutter-APK (тот же `applicationId`), так что фактически
это не потеря, а фиксация: если понадобится вернуть — писать провайдер заново на Kotlin
в `flutter/android/`.

### Фоновые проходы

Мгновенный режим (`lib/sync/mirror/mirror_live.dart`) работает, пока жив процесс: опрос головы
журнала раз в 3 с (в фоне приложения — раз в 30 с) и проход по событию файловой системы
(`FileObserver` через мост). Страховка на случай, когда процесса нет, — периодическое задание
системы: `JobScheduler`, id 4201, ровно 15 минут, `setPersisted(true)`, как в нативном клиенте.

Задание поднимает **свой** движок Flutter (`SyncJobService.kt`) и ставит в него тот же мост,
что и приложение. `workmanager` для этого не годится: в 0.10.x он создаёт движок внутри себя и
регистрирует только плагины из `GeneratedPluginRegistrant` — своего канала для `NativeFs` там
нет, а без номера файла переименование читалось бы как «удалил и залил заново».

Фоновый проход тихо ничего не делает, если задание снято, нет токена устройства, автоматика
выключена (`paused`) или приложение на экране (там работает мгновенный режим). Предохранители
движка не ослаблены: подтверждение массового удаления из фона не выставляется.

### Что нужно при первом запуске

1. Выдать «доступ ко всем файлам» — без него не видно ни дерева, ни содержимого (кнопка в
   «Настройках» → «Синхронизация»).
2. Отметить папки разделов «Файлы» и «Фото»: выбор прежнего нативного приложения не читается —
   он лежал в его собственных настройках, а Flutter пишет свой список (и это единственный клиент).
3. Убедиться, что не мешает старый токен устройства: корень зеркала заводится на каждый токен
   (`<Имя устройства> - Файлы`), поэтому у прежнего клиента в облаке может остаться своя папка.
   Отозвать ненужный токен можно в «Настройках» → «Токены приложений», после чего папку можно
   удалить как обычную.


## Релиз

Только через git и GitHub Actions; `adb install` — лишь когда это прямо попросили (например,
для проверки сборки на конкретном телефоне).

1. Поднять `versionCode` в `flutter/pubspec.yaml` (`version: 1.0.0+43`): телефон узнаёт об
   обновлении только по нему, и скрипт публикации не даёт положить сборку с тем же или меньшим
   номером.
2. Закоммитить и запушить в `main`: `./scripts/gh-push.sh main` (токен берётся из `~/work/.env`
   локально, в логи не попадает).
3. Запустить сборку: `gh workflow run android.yml --repo sobogd/cloudlyru`, дождаться успеха
   (`gh run watch <id> --exit-status`).
4. Что делает workflow (`.github/workflows/android.yml`): прогоняет тесты, собирает подписанный
   release-APK ключом из секретов (`flutter/android/keystore.properties`) и публикует его в S3.
   Постоянная ссылка —
   `https://files.iq-factura.com/apk`, её отдаёт и ручка `/api/v1/app/android`, по которой
   приложение в «Настройках» показывает доступное обновление.
