# websearch — поиск и чтение страниц для раздела «Чат»

Сервис живёт **на маке**, а не на сервере, и по двум причинам: браузер с обычным
отпечатком и домашний IP получают от поисковиков нормальную выдачу там, где HTTP-клиент
с VPS получает капчу; а сам мак и так держит модель, к которой сервер ходит через туннель.

## Ручки

| Ручка | Параметры | Что отдаёт |
|---|---|---|
| `GET /health` | — | `{"ok":true,"browser":"idle\|running","cache":{...}}` |
| `GET /search` | `q` (обязателен), `n` (1..10, по умолчанию 5) | `{"engine":"duckduckgo","results":[{title,url,snippet}]}` |
| `GET /page` | `url` (обязателен, только http/https), `max` (500..30000, по умолчанию 8000) | `{"url","title","lang","text","chars","truncated","short"}` |

В любом ответе есть поле `error`: `null` — получилось, строка — причина. Коды честные:
`400` — ошибка в запросе, `502` — сходить в интернет не удалось (капча, таймаут, все
движки молчат), `500` — внутренняя ошибка.

`short: true` (текст короче 400 символов) означает, что страница не прочитана: заглушка,
согласие на cookies, paywall. Серверу по этому признаку следует взять следующий источник,
а не отдавать модели пустоту.

## Запуск

```bash
# вручную, для отладки (порт по умолчанию 18814, можно переопределить WEBSEARCH_PORT)
/Users/sobogd/work/jevel.ai/agents/.venv-search/bin/python agents/websearch/server.py

# как служба
cp agents/websearch/com.agent.websearch.plist ~/Library/LaunchAgents/
launchctl load ~/Library/LaunchAgents/com.agent.websearch.plist
```

Playwright берётся из существующего venv `jevel.ai/agents/.venv-search` (в нём же лежат
браузерные библиотеки); системный Python для этого не годится. Браузер — установленный на
маке Chrome (`channel="chrome"`), отдельный Chromium не качается.

## Как это устроено

- **Один браузер, один поток.** Синхронный Playwright привязан к создавшему его потоку,
  поэтому браузер живёт в отдельном воркере, а HTTP-обработчики кладут задания в очередь.
  Задания выполняются по одному: параллельные чтения страниц дали бы выигрыш в секунды, но
  потребовали бы пула браузерных контекстов и вчетверо больше памяти на 16 ГБ маке.
- **Браузер закрывается после 10 минут простоя** и поднимается заново на следующем
  задании: держать Chrome (200-400 МБ) рядом с моделью на 6 ГБ незачем.
- **Кэш в памяти**: поиск 10 минут, страницы 30 минут, до 120 записей каждого вида.
  Один и тот же запрос приходит дважды чаще, чем кажется — человек переспрашивает, модель
  повторяет поиск, сервер перечитывает страницу после перезапуска.
- **Выдача движков по очереди**: DuckDuckGo (лучшая выдача и прямые ссылки), Startpage
  (индекс Google), Bing (ссылки в редирект-обёртке, которую разворачиваем). Mojeek
  выброшен — он отдаёт браузеру капчу. Ошибка движка не считается ошибкой поиска, это
  повод попробовать следующий.
