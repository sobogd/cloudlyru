# Cloudly — Android-клиент

Клиент телефона для личного облака CloudlyRu. Ставится APK-ом: нужен доступ ко всем файлам,
в Google Play такое приложение не идёт (см. `../ANDROID.md`).

## Что приложение делает сейчас (0.4.2)

Показывает, что лежит на телефоне, и отдаёт облако системному выбору файлов.

1. **Три раздела внизу:** «Файлы», «Фото», «Настройки».
2. **«Файлы»** — список файлов из выбранных папок, свежие (по дате изменения) сверху.
   Фото и видео сюда не попадают.
3. **«Фото»** — то же самое для фото и видео.
4. **«Очередь»** — отдельный раздел: что нашлось нового и изменённого в выбранных папках
   и ждёт выгрузки. Наполняется сама (при старте, после смены выбора папок, по кнопке),
   запуск файлов пока ручной и появится следующим шагом.
5. **Выбор папок** — отдельный экран на каждый раздел, а не диалог: всё дерево телефона раскрыто,
   отметка ставится галочкой в строке. Отмеченная папка включает все вложенные; снять галочку
   внутри отмеченной папки можно — выбранный предок при этом «раскрывается». Служебные каталоги
   (`Android/data`, `Android/obb`, скрытые имена, `.thumbnails`) в дереве не показываются.
6. **Настройки** — подключение к серверу, папки разделов и обновление приложения. Отдельного
   пункта «войти» нет: пока токена нет, форма входа показывается сама; когда вход выполнен —
   видно, под кем подключено, кнопки «Проверить подключение» и «Выйти».
7. **Облако в системном выборе файлов** — приложение видно в «Файлах», в диалогах сохранения и в
   «прикрепить файл» других приложений (например, в Telegram): дерево папок облака, миниатюры,
   открытие файла. Только чтение: запись в облако появится вместе с новым флоу загрузки.
   Если вход в аккаунт не выполнен, корень так и подписан — «вход не выполнен».

Разделение идёт **только папкой и разделом**: папка прикреплена к «Файлам» — её содержимое
идёт в файлы, прикреплена к «Фото» — в медиатеку, прикреплена к обоим — файл нужен в обоих
местах. Расширение используется только для иконки. Цели в облаке: «Файлы» — системная
неудаляемая папка «Телефон» (структура папок телефона копируется как есть), «Фото» —
медиатека (плоско).

## Синхронизации сейчас нет

В версии 0.4.0 удалены: движок автозагрузки, очередь и кэш выгруженного, фоновые воркеры и
`dataSync`-сервис, уведомления, «Поделиться», «Освободить место» и выбор папки облака. Флоу
загрузки переделывается, старый удалён целиком, чтобы не тащить его в новую модель.

Что осталось на месте: `net/Api.kt` — клиент REST сервера (вход, выпуск токена, версия сборки),
`update/Updater.kt` — обновление приложения по кнопке, `data/Prefs.kt` — адрес и токен.
В 0.4.2 вернулся провайдер документов (`docs/`), но только на чтение — без него облако не видно
в системном выборе файлов.

## Установка и первый запуск

1. Скачать APK: <https://files.iq-factura.com/apk> — ссылка постоянная, всегда отдаёт последнюю
   сборку. Дальше обновляться можно из самого приложения.
2. Открыть приложение → выдать «доступ ко всем файлам» (без него не видно ни дерева, ни файлов).
   Экран настроек Android открывается кнопкой прямо в приложении.
3. Настройки → войти логином владельца и паролем: приложение само выпустит device-токен и
   сохранит только его (пароль нигде не хранится).
4. Настройки → «Папки для файлов» и «Папки для фото и видео» → отметить нужные папки.
5. Разделы «Файлы» и «Фото» покажут содержимое отмеченных папок.

## Тесты

```bash
cd android
JAVA_HOME=/opt/homebrew/opt/openjdk@21 ./gradlew :app:testDebugUnitTest
```

Покрыты правила, ошибка в которых стоит потерянного файла или сломанного выбора: разделение
фото/файлы по расширению, служебные и недописанные файлы, дерево выбора папок (отметка вбирает
поддерево, снятие галочки раскрывает выбранного предка). Логика вынесена в
`device/MediaRules.kt` и `data/Selection.kt`, чтобы проверяться без устройства.

## Сборка на маке

```bash
brew install openjdk@21 gradle android-commandlinetools
sdkmanager --sdk_root=/opt/homebrew/share/android-commandlinetools \
  --install "platform-tools" "platforms;android-35" "build-tools;35.0.0"
yes | sdkmanager --sdk_root=/opt/homebrew/share/android-commandlinetools --licenses
# путь к SDK задаётся в android/local.properties (в git не попадает)

cd android
JAVA_HOME=/opt/homebrew/opt/openjdk@21 ./gradlew :app:assembleDebug   # android/app/build/outputs/apk/debug/
JAVA_HOME=/opt/homebrew/opt/openjdk@21 ./gradlew :app:assembleRelease # android/app/build/outputs/apk/release/
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Релиз подписывается ключом из `android/keystore.properties` (в git не попадает):
`~/.cloudly-android-release.jks`, создаётся `keytool -genkeypair`.

Публикация сборки: поднимите `versionCode` в `app/build.gradle.kts` и запушьте в `main` —
GitHub Actions (`.github/workflows/android.yml`) прогонит тесты, соберёт подписанный релиз и
выложит его по постоянной ссылке <https://files.iq-factura.com/apk>. Телефон увидит новую
версию по `versionCode`, кнопка «Обновить» в приложении подтянет именно её.

Вручную (перезалить уже собранный APK):

```bash
node --env-file=$HOME/work/.env scripts/publish-apk.mjs \
  android/app/build/outputs/apk/release/app-release.apk     # --dry-run: только показать
```

## Что нужно на телефоне после установки

1. «Доступ ко всем файлам» — без него не видно ни дерева папок, ни содержимого разделов.
2. Разрешить установку приложений из этого источника (`REQUEST_INSTALL_PACKAGES`) — иначе кнопка
   «Обновить» доведёт до диалога системы и остановится. Приложение само предложит открыть нужный
   экран настроек.

## Логи

`adb logcat -s cloudly-sync` — тег прежний, ошибки сети и входа пишутся в интерфейс
(текст ошибки видно в настройках, без похода в лог).
