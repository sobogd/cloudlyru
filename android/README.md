# CloudlyRu Sync — Android-клиент

Служебное приложение: загружает выбранные папки телефона в облако CloudlyRu и показывает облако
файловым браузером средствами Android. Ставится как APK (в Google Play не идёт — нужен доступ ко
всем файлам, см. `../ANDROID.md`).

Модель намеренно односторонняя и без автоматических удалений: приложение **только добавляет** файлы
в облако. Оно ничего не удаляет и не перезаписывает ни на телефоне, ни на сервере.

## Что умеет

1. **Автозагрузка папок.** Задача = папка телефона → папка облака. Обход папки, SHA-256,
   дедуп до передачи байтов (`/sync/have` + `init` с хэшем): если такое содержимое в облаке уже
   есть, байты не передаются вообще. Заливка частями прямо в S3 по presigned-ссылкам,
   продолжение после обрыва, ретраи с бэкоффом, при недоступности хранилища — автоматически
   через сервер (relay).
2. **Файловый браузер.** Облако видно в системных «Файлах», в выборе файлов и в диалогах
   сохранения (`CloudlyDocumentsProvider`): дерево папок, миниатюры фото и видео,
   открытие файла (качается в кэш с докачкой и проверкой хэша), создание папки,
   переименование, удаление (уходит в корзину сервера), «сохранить в облако» из другого
   приложения.
3. **«Поделиться».** Приложение появляется в системном списке «Поделиться»: папку получателя
   выбираешь прямо в нём, файлы уезжают сразу, не дожидаясь фонового прохода.
4. **«Освободить место».** Вручную и только по нажатию: удаляем с телефона то, что уже
   подтверждено в облаке и с момента выгрузки не менялось. В облаке копии остаются.
5. **Обновление по кнопке.** Приложение само проверяет, нет ли на сервере сборки новее
   (`GET /api/v1/app/android`), и по кнопке «Обновить» скачивает её с постоянной ссылки
   `/apk`, сверяет размер и sha256 и отдаёт системному установщику. Остаётся подтвердить
   установку в диалоге Android — браузер и поиск файла в «Загрузках» не нужны.

Чего приложение не делает принципиально: не удаляет файлы с телефона само, не удаляет и не
перезаписывает файлы в облаке по своей инициативе, не скачивает облако на телефон, не трогает
файлы телефона при изменениях в вебе. Удалили файл на телефоне — копия в облаке остаётся
(архив). Удалили в облаке — телефон не затрагивается.

## Установка и первый запуск

1. Скачать APK: <https://files.iq-factura.com/apk> — ссылка постоянная, всегда отдаёт
   последнюю сборку (что именно там лежит, видно в `/apk/version`). Дальше обновляться можно
   из самого приложения, кнопкой «Обновить».
2. Открыть приложение → выдать «доступ ко всем файлам», разрешение на уведомления, отключить
   оптимизацию батареи (кнопки на главном экране).
3. Ввести адрес сервера и войти логином владельца с паролем — приложение само выпустит
   device-токен и сохранит только его (пароль нигде не хранится, токен можно отозвать в вебе,
   не меняя пароль).
4. «Добавить папку»: **папка на телефоне** (файловый браузер с частыми папками DCIM, Pictures,
   Download и счётчиком файлов) → **папка в облаке** (выбор по дереву, с созданием папки на месте)
   → **зона**: «Фото» (сервер делает превью и показывает в таймлайне, файлы ложатся плоско) или
   «Файлы» (как есть, со структурой подпапок) → «только по Wi-Fi» при необходимости.
5. «Синхронизировать сейчас» — прогресс виден в уведомлении, кнопка «Стоп» останавливает.

## Фон

- WorkManager: периодический проход раз в 15 минут (живёт и после перезагрузки телефона) плюс
  запуск после добавления папки.
- Короткий `dataSync`-сервис — только на время активной передачи («Синхронизировать сейчас»),
  чтобы был прогресс и кнопка «Стоп». Android 15 ограничивает такой сервис шестью часами в сутки,
  поэтому постоянного сервиса нет.
- Уведомление о проблемах: сколько ошибок, пример первой. При чистом проходе снимается.

## Тесты

```bash
cd android
JAVA_HOME=/opt/homebrew/opt/openjdk@21 ./gradlew :app:testDebugUnitTest
```

Покрыты правила, ошибка в которых стоит файлов: ожидание Wi-Fi, «слишком свежий» файл, свободное
имя с суффиксом (чужое имя не перезаписываем), очистка имени от пути и управляющих символов,
распознавание переименований по содержимому, обход папок сканером. Логика вынесена в
`sync/Decisions.kt` и `sync/Hasher.kt`, чтобы проверяться без устройства.

## Сборка на маке

```bash
brew install openjdk@21 gradle android-commandlinetools
sdkmanager --sdk_root=/opt/homebrew/share/android-commandlinetools \
  --install "platform-tools" "platforms;android-35" "build-tools;35.0.0"
yes | sdkmanager --sdk_root=/opt/homebrew/share/android-commandlinetools --licenses
# путь к SDK задаётся в android/local.properties (в git не попадает)

cd android
JAVA_HOME=/opt/homebrew/opt/openjdk@21 ./gradlew :app:assembleDebug   # android/app/build/outputs/apk/debug/
JAVA_HOME=/opt/homebrew/opt/openjdk@21 ./gradlew :app:assembleRelease # android/app/build/outputs/apk/release/
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Релиз подписывается ключом из `android/keystore.properties` (в git не попадает):
`~/.cloudly-android-release.jks`, создаётся `keytool -genkeypair`.

Публикация сборки: поднимите `versionCode` в `app/build.gradle.kts` и запушьте в `main` —
GitHub Actions (`.github/workflows/android.yml`) прогонит тесты, соберёт подписанный релиз и
выложит его по постоянной ссылке <https://files.iq-factura.com/apk>. Телефон увидит новую
версию по `versionCode`, кнопка «Обновить» в приложении подтянет именно её.

Вручную (перезалить уже собранный APK):

```bash
node --env-file=$HOME/work/.env scripts/publish-apk.mjs \
  android/app/build/outputs/apk/release/app-release.apk     # --dry-run: только показать
```

## Что нужно на телефоне после установки

1. «Доступ ко всем файлам» — без него не видно корень Download и произвольные папки.
2. Разрешение на уведомления (прогресс и кнопка «Стоп»).
3. Отключить оптимизацию батареи — на агрессивных прошивках (Xiaomi/Huawei/Samsung) иначе
   фоновые задачи не запускаются, см. <https://dontkillmyapp.com/>.
4. Разрешить установку приложений из этого источника (`REQUEST_INSTALL_PACKAGES`) — иначе
   кнопка «Обновить» доведёт до диалога системы и остановится. Приложение само предложит
   открыть нужный экран настроек.

## Журнал и диагностика

Состояние видно на главном экране: сколько операций в очереди, итог прошлого прохода, текст
последней ошибки, отдельно — «Не прошло» с причиной по каждому файлу. Кнопки «Проверить токен» и
«Диагностика сети» показывают, что именно не работает: DNS, доступность сервера, доступность
хранилища. Логи приложения: `adb logcat -s cloudly-sync`.
